#+begin_example
从市场发现和安装插件，以使用新 skills、agents 和功能扩展 Claude Code
#+end_example

插件通过 skills、agents、hooks 和 MCP servers 扩展 Claude Code。插件市场是帮助您发现和安装这些扩展的目录，无需自己构建

想要创建和分发自己的市场？请参阅[[https://code.claude.com/docs/zh-CN/plugin-marketplaces][创建和分发插件市场]]

* 市场如何工作
市场是他人创建和共享的插件目录。使用市场是一个两步过程：
1. 添加市场：这会向 Claude Code 注册目录，以便可以浏览可用内容。尚未安装任何插件
2. 安装单个插件：浏览目录并安装您想要的插件

#+begin_example
  可以将其视为添加应用商店：添加商店让可以访问浏览其集合，但仍然需要单独选择要下载的应用
#+end_example

* 官方 Anthropic 市场
官方 Anthropic 市场 _claude-plugins-official_ 在启动 Claude Code 时自动可用。运行 */plugin* 并转到发现选项卡以浏览可用内容，或在 *claude.com/plugins* 查看目录

要从官方市场安装插件，请使用 _/plugin install <name>@claude-plugins-official_ 。例如，要安装 GitHub 集成：

#+begin_src sh 
  /plugin install github@claude-plugins-official
#+end_src

如果 Claude Code 报告在任何市场中找不到该插件，则市场要么缺失，要么已过期。运行 _/plugin marketplace update claude-plugins-official_ 以刷新它，或如果之前未添加过，运行 _/plugin marketplace add anthropics/claude-plugins-official_ 。然后重试安装

#+begin_example
  官方市场由 Anthropic 维护，包含由 Anthropic 自行决定的内容

  应用内提交表单将插件添加到社区市场，而不是官方市场

  要独立分发插件，请创建您自己的市场并与用户共享
#+end_example

官方市场包括多个插件类别

** 代码智能
代码智能插件启用 Claude Code 的内置 LSP 工具，使 Claude 能够跳转到定义、查找引用并在编辑后立即查看类型错误。这些插件配置[[https://microsoft.github.io/language-server-protocol/][语言服务器协议连接]]，这是为 VS Code 代码智能提供支持的相同技术

这些插件需要在系统上安装语言服务器二进制文件。如果已经安装了语言服务器，当打开项目时，Claude 可能会提示安装相应的插件
| 语言       | 插件              | 所需二进制文件             |
| C/C++      | clangd-lsp        | clangd                     |
| C#         | csharp-lsp        | csharp-ls                  |
| Go         | gopls-lsp         | gopls                      |
| Java       | jdtls-lsp         | jdtls                      |
| Kotlin     | kotlin-lsp        | kotlin-language-server     |
| Lua        | lua-lsp           | lua-language-server        |
| PHP        | php-lsp           | intelephense               |
| Python     | pyright-lsp       | pyright-langserver         |
| Rust       | rust-analyzer-lsp | rust-analyzer              |
| Swift      | swift-lsp         | sourcekit-lsp              |
| TypeScript | typescript-lsp    | typescript-language-server |

也可以 [[https://code.claude.com/docs/zh-CN/plugins-reference#lsp-servers][为其他语言创建自己的 LSP 插件]]

#+begin_example
  如果在安装插件后在 /plugin 错误选项卡中看到 Executable not found in $PATH，请从上表安装所需的二进制文件
#+end_example

*** Claude 从代码智能插件获得的功能
安装代码智能插件并且其语言服务器二进制文件可用后，Claude 获得两项功能：
+ 自动诊断：在 Claude 进行的每次文件编辑后，语言服务器分析更改并自动报告错误和警告。Claude 看到类型错误、缺失导入和语法问题，无需运行编译器或 linter
  + 如果 Claude 引入错误，它会注意到并在同一轮中修复问题。这不需要除安装插件外的任何配置
  + 当”发现诊断”指示器出现时，可以按 Ctrl+O 来内联查看诊断
+ 代码导航：Claude 可以使用语言服务器跳转到定义、查找引用、获取悬停时的类型信息、列出符号、查找实现和追踪调用层次结构
  #+begin_example
    这些操作为 Claude 提供比基于 grep 的搜索更精确的导航，尽管可用性可能因语言和环境而异
  #+end_example

#+begin_example
如果遇到问题，请参阅代码智能故障排除

https://code.claude.com/docs/zh-CN/discover-plugins#code-intelligence-issues
#+end_example

* 尝试：添加演示市场
Anthropic 还维护一个 *演示插件市场* _claude-code-plugins_ ，其中包含展示插件系统可能性的示例插件。与官方市场不同，需要手动添加此市场
1. 添加市场：在 Claude Code 中，为 anthropics/claude-code 市场运行 _plugin marketplace add_ 命令：
   #+begin_src sh 
     /plugin marketplace add anthropics/claude-code
   #+end_src
   这会下载市场目录并使其插件对您可用
2. 浏览可用插件：运行 /plugin 打开插件管理器。这会打开一个选项卡式界面，有四个选项卡，可以使用 Tab 循环切换（或使用 Shift+Tab 向后切换）：
   + 发现：从所有市场浏览可用插件
   + 已安装：查看和管理已安装的插件
   + 市场：添加、删除或更新已添加的市场
   + 错误：查看任何插件加载错误
     转到 *发现* 选项卡以查看刚添加的市场中的插件
     #+begin_example
       当管理员通过 pluginSuggestionMarketplaces 托管设置将市场列入允许列表时

       标记为与当前工作目录相关的插件会在顶部固定，并带有建议用于此目录标签
     #+end_example
3. 安装插件，选择一个插件以查看其详细信息。详细信息窗格显示插件包含的内容及其成本：
   + 上下文成本估计，因此可以查看插件将在每个回合中向您的上下文窗口添加多少个令牌（Claude Code v2.1.143 及更高版本）
   + 插件的最后更新日期（v2.1.144 及更高版本）
   + 一个将安装部分，列出插件的命令、agents、skills、hooks 和 MCP 及 LSP 服务器，因此可以在安装前查看它添加的确切内容（v2.1.145 及更高版本）
     选择安装范围：
     + 用户范围：在所有项目中为自己安装
     + 项目范围：为此存储库上的所有协作者安装
     + 本地范围：仅在此存储库中为自己安装
       #+begin_example
	 例如，选择 commit-commands（添加 git 工作流 skills 的插件）并将其安装到您的用户范围
       #+end_example
       也可以从命令行直接安装：
       #+begin_src sh 
	 /plugin install commit-commands@claude-code-plugins
       #+end_src
       #+begin_example
	 请参阅配置范围以了解有关范围的更多信息

	 https://code.claude.com/docs/zh-CN/settings#configuration-scopes
       #+end_example
4. 使用您的新插件，安装后，运行 _/reload-plugins_ 以激活插件
   + 插件 skills 由插件名称命名空间，因此 commit-commands 提供诸如 /commit-commands:commit 之类的 skills
   + 通过对文件进行更改并运行来尝试：
     #+begin_src sh 
       /commit-commands:commit
     #+end_src
     #+begin_example
       这会暂存您的更改、生成提交消息并创建提交
     #+end_example
     每个插件的工作方式不同。检查 *发现* 选项卡中的插件详细信息以查看它提供的命令和 skills，或访问其主页以获取使用指导

#+begin_example
每个插件的工作方式不同。检查发现选项卡中的插件详细信息以查看它提供的命令和 skills，或访问其主页以获取使用指导
#+end_example

* 添加市场

使用 */plugin marketplace add* 命令从不同来源添加市场：
+ GitHub 存储库：owner/repo 格式
  #+begin_example
    例如 anthropics/claude-code
  #+end_example
+ Git URL：任何 git 存储库 URL，包括 GitLab、Bitbucket 和自托管服务器
+ 本地路径：目录或 marketplace.json 文件的直接路径
+ 远程 URL：托管 marketplace.json 文件的直接 URL

#+begin_example
快捷方式：可以使用 /plugin market 代替 /plugin marketplace，以及使用 rm 代替 remove
#+end_example

** 从 GitHub 添加
使用 owner/repo 格式添加包含 .claude-plugin/marketplace.json 文件的 GitHub 存储库，其中 owner 是 GitHub 用户名或组织，repo 是存储库名称

#+begin_example
例如，anthropics/claude-code 指的是由 anthropics 拥有的 claude-code 存储库
#+end_example

#+begin_src sh 
  /plugin marketplace add anthropics/claude-code
#+end_src

** 从其他 Git 主机添加
通过提供完整 URL 添加任何 git 存储库。这适用于任何 Git 主机，包括 GitLab、Bitbucket 和自托管服务器。包括 .git 后缀，以便 Claude Code 克隆存储库，而不是将 URL 视为托管 marketplace.json 文件的直接链接。注意：同时包括 https:// 前缀
#+begin_example
  Claude Code v2.1.196 及更高版本会拒绝没有前缀的主机，例如 gitlab.com/company/plugins.git，将其视为无效的 GitHub owner/repo 简写

  错误消息会告诉添加前缀。早期版本会将其误读为 GitHub 存储库路径，并在克隆时失败
#+end_example
+ 使用 HTTPS：
  #+begin_src sh 
    /plugin marketplace add https://gitlab.com/company/plugins.git
  #+end_src
+ 使用 SSH：
  #+begin_src sh 
    /plugin marketplace add git@gitlab.com:company/plugins.git
  #+end_src


要添加特定分支或标签，请在 # 后附加 ref：
#+begin_src sh 
  /plugin marketplace add https://gitlab.com/company/plugins.git#v1.0.0
#+end_src

** 从本地路径添加
添加包含 .claude-plugin/marketplace.json 文件的本地目录：
#+begin_src sh 
  /plugin marketplace add ./my-marketplace
#+end_src

也可以添加 marketplace.json 文件的直接路径：
#+begin_src sh 
  /plugin marketplace add ./path/to/marketplace.json
#+end_src

** 从远程 URL 添加
通过 URL 添加远程 marketplace.json 文件：
#+begin_src sh 
  /plugin marketplace add https://example.com/marketplace.json
#+end_src

#+begin_example
  与基于 Git 的市场相比，基于 URL 的市场有一些限制

  如果在安装插件时遇到”路径未找到”错误，请参阅故障排除

  https://code.claude.com/docs/zh-CN/plugin-marketplaces#plugins-with-relative-paths-fail-in-url-based-marketplaces
#+end_example

* 安装插件
添加市场后，可以直接安装插件：
#+begin_src sh 
  /plugin install plugin-name@marketplace-name
#+end_src

该命令打开该插件的详情，可以在其中选择[[https://code.claude.com/docs/zh-CN/settings#configuration-scopes][安装范围]]。运行 /plugin，转到 *发现* 选项卡，然后在插件上按 _Enter_ 时，会看到相同的选择：
+ 用户范围（默认）：在所有项目中为自己安装
+ 项目范围：为此存储库上的所有协作者安装，这会将插件添加到 .claude/settings.json
+ 本地范围：仅在此存储库中为自己安装，不与协作者共享

#+begin_example
  也可能看到具有托管范围的插件。这些由管理员通过托管设置安装，无法修改
#+end_example

要在没有交互式步骤的情况下安装，请使用 _claude plugin install_ shell 命令，该命令默认安装到用户范围，除非传递 --scope

#+begin_example
  在安装插件之前，请确保信任该插件

  Anthropic 不控制插件中包含的 MCP servers、文件或其他软件，也无法验证它们是否按预期工作

  检查每个插件的主页以获取更多信息
#+end_example

* 管理已安装的插件
运行 /plugin 并转到已安装选项卡以 _查看_ 、 _启用_ 、 _禁用_ 或 _卸载_ 插件。该列表按范围分组并排序，以便首先看到问题：具有加载错误或未解决依赖项的插件出现在顶部，然后是收藏夹，禁用的插件折叠在底部的折叠标题后面。从列表中可以：
+ 按 f 以收藏或取消收藏选定的插件
+ 输入以按插件名称或描述筛选
+ 按 Enter 打开插件的详细视图并启用、禁用或卸载它

卸载项目的 _.claude/settings.json_ 启用的插件会询问指的是哪个范围：
+ 仅为您禁用它，这会将覆盖写入 .claude/settings.local.json 并为项目保留已安装的插件
+ 为所有人卸载它，这会将其从共享的 .claude/settings.json 中删除
  #+begin_example
    需要 Claude Code v2.1.203 或更高版本。在 v2.1.203 之前，对话框仅提供本地禁用选项
  #+end_example

*详细视图* 显示插件贡献的组件：commands、skills、agents、hooks、MCP servers 和 LSP servers。相同的清单也可以从命令行通过 _claude plugin details_ 获得

*已安装选项卡* 还收集您自己安装但至少两周内未使用过的市场插件，跨越至少 10 个会话，在 *最近未使用* 标题下。详细视图为每个插件显示一条最后使用行。使用这些来查找您不再使用但仍在增加启动和上下文成本的插件，然后禁用或卸载它们
#+begin_example
需要 Claude Code v2.1.187 或更高版本
#+end_example

两种类型的插件永远不会被列为未使用：
+ 您的组织管理的插件或您使用 --plugin-dir 加载的插件
+ 贡献主题、输出样式、监视器或工作流的插件，因为这些提供的价值无需跟踪调用

#+begin_example
当您的组织使用 strictKnownMarketplaces 限制市场时，最近未使用标题和最后使用行都被隐藏
#+end_example

插件的 *语言服务器* 在提供诊断或回答代码导航请求时被计为已使用，因此其服务器在会话中处于活跃状态的 LSP 插件不会被列为未使用
#+begin_example
  在 v2.1.203 之前，无法计算语言服务器活动作为使用，因此贡献 LSP 服务器的插件完全免除

  与主题和输出样式插件仍然相同的方式
#+end_example

在计算语言服务器活动的版本的第一个会话中，还会重置每个尚未记录任何使用的 LSP 插件的使用记录，因此 Claude Code 不会根据在其服务器活动被跟踪之前记录的数据将您之前安装的插件判断为未使用
#+begin_example
在 v2.1.206 之前，该第一个会话可能会在最近未使用下列出一个活跃使用的 LSP 插件并建议审查它
#+end_example

当安装声明依赖项的插件时，安装输出会列出哪些依赖项与其一起自动安装

** 使用直接命令管理插件
列出已安装的插件而不打开菜单：
#+begin_src sh 
  /plugin list
#+end_src

#+begin_example
传递 --enabled 或 --disabled 以仅显示处于该状态的插件
#+end_example

禁用插件而不卸载：
#+begin_src sh 
  /plugin disable plugin-name@marketplace-name
#+end_src

重新启用已禁用的插件：
#+begin_src sh 
  /plugin enable plugin-name@marketplace-name
#+end_src

在这些标识符中，plugin-name 是 marketplace entry 中插件的 name，它可能与插件自己的 plugin.json 中的 name 不同

#+begin_example
  从 Claude Code v2.1.195 开始，/plugin 界面中的启用和禁用适用于两个名称不同的插件，/plugin enable 和 /plugin disable 接受任一名称

  当在早期版本中禁用此类插件时，Claude Code 报告 already disabled 并将其保持启用状态
#+end_example

完全删除插件：
#+begin_src sh 
  /plugin uninstall plugin-name@marketplace-name
#+end_src

--scope 选项允许使用 CLI 命令针对特定范围：

#+begin_src sh 
  claude plugin install formatter@your-org --scope project
  claude plugin uninstall formatter@your-org --scope project
#+end_src

** 应用插件更改而不重启
当在会话期间安装、启用或禁用插件时，运行 /reload-plugins 以在不重启的情况下获取所有更改：

#+begin_src sh 
  /reload-plugins
#+end_src

Claude Code 重新加载所有活跃插件，并显示插件、skills、agents、hooks、插件 MCP servers 和插件 LSP servers 的计数

#+begin_example
  重新加载在下一个请求时会产生令牌成本：新加载的组件在附加到对话的内容中宣布自己，而现有历史记录仍然从 prompt cache 读取

  提供 MCP servers 的插件在其工具未被 tool search 延迟时成本更高

  该更改使缓存失效，下一个请求重新读取整个对话
#+end_example

在这种情况下，/reload-plugins 显示警告并不应用重新加载；传递 _--force_ 以强制应用。有关详细信息，请参阅[[https://code.claude.com/docs/zh-CN/prompt-caching#enabling-or-disabling-a-plugin][启用或禁用插件]]

** 使用交互式界面

#+end_src

  删除市场将卸载从中安装的任何插件
#+end_example

** 配置自动更新
Claude Code 可以在启动后在后台自动更新市场及其已安装的插件。为市场启用自动更新后，Claude Code 会刷新市场数据并将已安装的插件更新到磁盘上的最新版本

#+begin_example
  Claude Code 在会话启动后检查市场和插件更新，延迟时间最多为十分钟，因此运行中的会话继续使用它在启动时加载的版本

  如果任何插件已更新，将看到提示运行 /reload-plugins 的通知，或新版本在您下次启动时加载
#+end_example

通过 UI 为单个市场切换自动更新：
1. 运行 /plugin 打开插件管理器
2. 选择市场
3. 从列表中选择市场
4. 选择启用自动更新或禁用自动更新

官方 Anthropic 市场默认启用自动更新。第三方和本地开发市场默认禁用自动更新

#+begin_example
  管理员还可以在托管设置中的每个 extraKnownMarketplaces 条目上设置 "autoUpdate": true

  以为组织市场启用自动更新，而无需每个用户都切换
#+end_example

要完全禁用 Claude Code 和所有插件的所有自动更新，请设置 DISABLE_AUTOUPDATER 环境变量
#+begin_example
  有关详细信息，请参阅自动更新

  https://code.claude.com/docs/zh-CN/setup#auto-updates
#+end_example
要在禁用 Claude Code 自动更新的同时保持插件自动更新启用，请设置 FORCE_AUTOUPDATE_PLUGINS=1 以及 DISABLE_AUTOUPDATER：
#+begin_src sh 
  export DISABLE_AUTOUPDATER=1
  export FORCE_AUTOUPDATE_PLUGINS=1
#+end_src

#+begin_example
当想手动管理 Claude Code 更新但仍接收自动插件更新时，这很有用
#+end_example

* 故障排除

** /plugin 命令无法识别
如果看到”未知命令”或 /plugin 命令未出现：
1. 检查版本：运行 claude --version 以查看安装的内容
2. 更新 Claude Code：
   + Homebrew：brew upgrade claude-code，或如果您安装了该 cask，则为 brew upgrade claude-code@latest
   + npm：npm install -g @anthropic-ai/claude-code@latest
   + 本地安装程序：从设置重新运行安装命令
3. 重启 Claude Code：更新后，重启您的终端并再次运行 claude

** 常见问题
+ 市场未加载：验证 URL 是否可访问以及 .claude-plugin/marketplace.json 是否存在于该路径
+ 插件安装失败：检查插件源 URL 是否可访问以及存储库是否公开，或是否有访问权限
+ 安装后找不到文件：插件被复制到缓存，因此引用插件目录外文件的路径将不起作用
+ 插件 skills 未出现：使用 rm -rf ~/.claude/plugins/cache 清除缓存，重启 Claude Code，然后重新安装插件

** 代码智能问题
+ 语言服务器未启动：验证二进制文件已安装且在您的 $PATH 中可用
  #+begin_example
    检查 /plugin 错误选项卡以获取详细信息
  #+end_example
+ 高内存使用：rust-analyzer 和 pyright 等语言服务器在大型项目上可能消耗大量内存
  #+begin_example
    如果遇到内存问题，请使用 /plugin disable <plugin-name> 禁用插件，并改为依赖 Claude 的内置搜索工具
  #+end_example
+ monorepos 中的误报诊断：如果工作区配置不正确，语言服务器可能会报告内部包的未解析导入错误
  #+begin_example
    这些不会影响 Claude 编辑代码的能力
  #+end_example
